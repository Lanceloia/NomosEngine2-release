## 要让读者看懂什么

- 用世界规则支援 RPG/TRPG 沙盒，而不是把所有选择预写为剧情分支。
- 只改救人规则，开局数据与行动见证相同。
- 两版各自编译、开局、运行，不是同一会话中途热改或分支历史。
- B 是女巫，也是本夜被袭击者；她请求救自己。
- 原版发布救人 Action 及后续 Event，编辑版拒绝请求、不发布本次行动。

不解释整套 C0/K0/T0 架构，不演示最终胜负、生还或完整 TRPG；这些不由本例证明。

## 连续动画

| 秒数 | 变化及注意力 |
| --- | --- |
| 0–2 | 两个独立运行区、各自 B、用途和相同输入已在场；输出为空 |
| 2–4 | 仅编辑版新增条件整行揭示并停留，保留中文释义；不模拟打字或编译进度 |
| 4–6 | 两侧同步描出 B 的自指弧线，让读者看见行动者和目标相同 |
| 6–8 | 相同空心请求框同步出现，下移约 60px 接近各自判定边界；B 和规则不动 |
| 8–10 | 停住，确认对照的是同一请求；结果还未出现 |
| 10–12 | 两侧结果同步开始：原版连线穿过边界，生成 `救人行动已发布`；编辑版线止于边界，显示 `请求被拒绝` |
| 12–14 | 原版第一条记录连向 `后续结算已发布`；编辑版显示 `本次不发布`，不出现空记录或删除动画 |
| 14–17 | 显现末态证据：`前9步：12条完整记录一致`、`第10步请求后：原版14条／编辑版12条` |
| 17–22 | 同屏静止五秒，规则、身份关系、请求和发布结果同时可见 |
| 22–23 | 中性演示遮罩明确写 `重看对照`，切回首帧；不倒放、撤销或逐条擦除世界记录 |

空心请求始终是提议，不能变成已发布 Action；发布记录在自己的位置独立生成。
运动表达关系和讲解顺序，不表达实际耗时。保留一个完整末态作为静态 PNG。
