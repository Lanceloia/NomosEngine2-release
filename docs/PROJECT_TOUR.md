# 从作者规则到实际故事

NomosEngine2 是一套规则世界的编译、执行与验证工具。
它希望服务于 RPG/TRPG 沙盒：作者定义哪些事情允许发生、怎样产生后果，
玩家或 Agent 决定做什么；剧情是实际行动形成的历史，而不是执行器预写的分支树。

当前展示的重点是这条工程链已经可运行，不是宣称实现了通用 LLM 主持人。

## 先看三个实验

按根 README 安装后，从仓库根运行下列命令。工具只在内存编辑输入，不改作者文件。
Windows 将 `.venv/bin/python` 换为 `.venv\Scripts\python.exe`。

| 实验与命令 | 只改什么 | 应观察到什么 |
| --- | --- | --- |
| `.venv/bin/python tools/release_rule_edit_demo.py` | 女巫救人 Law 增加禁止自救条件 | 前九步来源相同，第十步由成功变为 K0 拒绝；这次行动不发布 |
| `.venv/bin/python tools/release_wolf_vote_demo.py` | 共同袭击从全票一致换为多数票 | 同十次行动均发布，但前者无人死亡，后者 F 死亡 |
| `.venv/bin/python tools/release_world_edit_demo.py` | 女巫换人，或增加参与者及其开局 | 信息、选项和来源转到 E；G/H 有各自视图，G 实际投票 |

三个实验合起来说明：编译的不只是固定按钮，也不只是参数；规则引用、参与者与开局
共同决定真实行为。它们都复用同一个编译器和内核，不由工具直接写入世界终态。

同时核对限制：禁自救实验中救人候选仍会出现，最终准入才拒绝；换职业须同步角色表和
本人药水开局；增加人数不是仅改一个数字。这些都是可见的当前边界，不藏在演示背后。
逐步证据与源码差异见[规则准入](SHOWCASE.md)、[世界后果](showcase/wolf-vote/README.md)、
[人物与人数](showcase/world-edits/README.md)。JSON 是完整审计证据，首次阅读先看这些中文摘要。

## 作者到底写什么

| 文件 | 回答的问题 |
| --- | --- |
| Lib | 状态有哪些类型？可复用的 Law 定义是什么？ |
| Ports | 这项规则可以读谁、写什么、接收哪些参与者？ |
| Source | 本世界有哪些实例、选择哪些 Law、把能力授予谁、怎样控制与呈现？ |
| Assets | 这一次开局的职业、位置、资源和其他状态是什么？ |
| 行动见证 | 外部控制者希望尝试什么行动，以及检查什么目标？ |

前四者创建可玩世界；最后一项是 T0 的独立检查输入，不是剧情程序。
Source 不规定玩家一定救谁、一定走哪条路线。

字段写法也尽量让意图可读：先集中声明领域类型，再写 `ParticipantName id`、
`RoundNumber round`；条件写 `actor.name != scene.pending_attack`，集合判断用存在、
无匹配和唯一匹配谓词。它们会进入受检的类型与表达式，而不是把 Python 放进 YAML 执行。
亲手修改见[作者指南](AUTHORING.md)、[类型与字段](C0_LIB_TYPE_ALIASES_V1.md)。

## 实际执行路径

```text
Lib + Ports + Source -> C0 检查与编译 -> Program
Program + Assets -> Start -> K0 Session
当前选项 -> 提交行动 -> 当前态重核 -> 原子发布状态与发生记录
Program + Assets + 有限见证 -> T0 实际运行并检查结果
```

这里有三项重要取舍：

1. **候选不是许可证明。** 菜单提供行动提议，K0 在提交时重验当前状态，防止过时或越权请求。
2. **世界真相不是玩家知识。** 玩家读取受限的本人投影；作者审计可以查看权威状态，二者不混用。
3. **验证器不另模拟世界。** T0 使用同一 Program 和 Session 实际执行见证；
   一条见证失败，不等于所有可能路线都不可达。

沿一条救人规则读实现，见[代码导览](CODE_MAP.md)；原子结算与已知边界见
[K0](../engine/kernel/README.md)，具名反例见[测试地图](TESTING.md)。

## 与游戏 Agent 的关系

已经具备的是有限规则环境、受限本地视图、行动提交、发生来源和见证检查。
冰宫样例还使用有限 Appraisal 对实际选项评分，不是通用规划器。

未来的 LLM Agent 可以读取授权信息、提出行动，或为作者草拟规则资产；LLM DM 可以讲述
已经发生的故事。编译检查、规则准入与世界权威仍由确定性的工程链负责，不让模型直接
改写任意状态。这是未来接入方向，当前仓库没有完成 LLM 训练、记忆系统或通用 DM。

## 项目贡献与边界

项目发起者负责问题定义、世界建模目标、语义裁决、优先级和亲自验收；
后期主要代码由 Codex 及协作者实现或审阅。不能把这份仓库描述成全部个人手写代码。
技术讨论应当能落到源码、反例和真实实验，不能只用协作过程替代对实现的理解。

本展示版尚不提供通用存档恢复、多人身份服务或任意题材的完整 TRPG。
M1 是带许可署名的有限改编，且独立 Web 消费冻结版；不把其截图当作本仓库最新核心的运行证据。
已有与待研究的范围统一见[语义说明](SEMANTICS.md)、[展示矩阵](SHOWCASE_MATRIX.md)。
